# CMP 90HX compute + PCIe Gen2 (VBIOS 94.02.74.00.07)

Everything below was generated by AI, but the result was confirmed.

## Pipeline

```
NVIDIA Open 610.43.03 userspace + GSP firmware
        ↓
pearlfortune stockflow 0001–0015   →  compute unlock (survives reboot)
        ↓
jdowning100 0016 + this 0017        →  rebuild nvidia*.ko
        ↓
cold boot: consume.sh (34 reloads) →  hammer.sh (retrain, then stop)
        ↓
Gen2 x4 (this board) + full-rate compute
```

| Step | Repo |
| --- | --- |
| Compute | [pearlfortune/cmpunlocker](https://github.com/pearlfortune/cmpunlocker) 90HX stockflow, Open **610.43.03**, `0001`–`0015` |
| PCIe `.01` / `.05` | jdowning100 rejoin16 (`0016`) — use that write-up, not this one |
| PCIe **`.07`** | this repo (`0017`) |

Card: `10de:220d` / `1555`. Secure Boot off. Kernel headers installed.

---

### A. Userspace driver

```sh
wget https://download.nvidia.com/XFree86/Linux-x86_64/610.43.03/NVIDIA-Linux-x86_64-610.43.03.run
chmod +x NVIDIA-Linux-x86_64-610.43.03.run
sudo ./NVIDIA-Linux-x86_64-610.43.03.run --silent --no-kernel-modules
# expect /lib/firmware/nvidia/610.43.03/gsp_ga10x.bin
```

### B. Compute unlock (pearlfortune)

Their stockflow inlines V67 into driver init: opens FEAT, writes SS0/SS1. After this, compute stays unlocked across reboot.

Easiest path — from their tree:

```sh
sudo ./install.sh --profile=cmp90-rejoin15
sudo reboot
```

Or the v0.1.28 90HX stockflow bundle (`build-candidate.sh` + `stockflow-install.sh`). See their README for checksums.

On this card: locked FP32 **0.72 TFLOPS** → mid-teens after stockflow. Confirm compute before touching PCIe.

### C. PCIe Gen2 modules (0016 + 0017)

Start from the same 610.43.03 kernel source stockflow already used. Apply jdowning100 `0016`, then this patch:

```sh
patch -p1 < patches/0017-6104303-cmp90hx-vbios07-pcie-gen2.patch
cd kernel-open
MAKEFLAGS='CC=gcc-14' make -j"$(nproc)" modules
```

If you use jdowning100’s `build-candidate-with-rejoin16.sh`, set `CMP90_STOCKFLOW_VARIANT=rejoin16`, then apply `0017` on that work tree and rebuild.

```sh
sudo mkdir -p /lib/modules/$(uname -r)/updates/cmpunlocker-90hx-stockflow
sudo install -m644 nvidia.ko nvidia-uvm.ko nvidia-modeset.ko nvidia-drm.ko nvidia-peermem.ko \
  /lib/modules/$(uname -r)/updates/cmpunlocker-90hx-stockflow/
sudo depmod
```

### D. Apply PCIe once per cold boot

Masks re-lock after a real power cycle. Warm `rmmod` keeps them.

```sh
gcc -O2 -o scripts/bar0rw scripts/bar0rw.c
sudo scripts/cmp90hx-gen2-consume.sh    # ~34 insmod cycles, several minutes
sudo scripts/cmp90hx-gen2-hammer.sh     # Retrain-Link until LnkSta is Gen2, then exit
```

If the GPU vanishes, power off ≥ 60 s. Do not loop FLR/SBR.

```sh
cat /sys/bus/pci/devices/<BDF>/current_link_speed    # 5.0 GT/s PCIe
sudo setpci -s <BDF> CAP_EXP+12.w                    # 1042 = Gen2
```

Do not write LnkCap. TLS is `CAP_EXP+30`. Do not write `PL_LINK_RATE` `0x00240036`. Don’t poll `nvidia-smi` every second.

`systemd/` can run D at boot (consume, then hammer). Fix `ExecStart` paths first.

## Notes

- Slot is physically x16; BIOS split it to x8; this card still trained **x4**.
- Some 90HX already train x16. Dual GPU: same pipeline per card.
- BAR0 `0xffffffff` → cold reboot. Don’t set Link Disable with the driver loaded.
